# Contributing

We welcome contributions to this project!

Please feel free to:
- Report a bug or issue
- Discuss the current state of the course materials
- Submit a fix or improvement
- Propose new features or content
- Suggest enhancements to exercises or examples

## We Develop with GitHub

We use GitHub to host course materials, track issues and enhancement requests, as well as accept pull requests.

## All Changes Happen Through Pull Requests

Pull requests are the best way to propose changes to the course materials. We actively welcome your pull requests:

1. Fork the repo and create your branch from `main`.
2. If you've added new content (exercises, slides, examples), ensure it follows the existing structure and formatting.
3. If you've changed course content or learning objectives, update the relevant documentation (README, learning objectives, etc.).
4. Test that the Quarto website renders without errors: `quarto render`
5. Make sure your Markdown and R code are well-formatted and readable.
6. Submit that pull request!

## Any Contributions You Make Will Be Under the MIT Software License

In short, when you submit changes, your submissions are understood to be under the same [MIT License](http://choosealicense.com/licenses/mit/) that covers the project. Feel free to contact the maintainers if that's a concern.

## Report Bugs Using GitHub's [Issues](https://github.com/DQBM-CCCZ/publication_ready_figs_R/issues)

We use GitHub issues to track public bugs and feature requests. Report an issue by [opening a new issue](https://github.com/DQBM-CCCZ/publication_ready_figs_R/issues/new); it's that easy!

## Write Detailed Issue Reports

**Great Issue Reports** tend to have:

- A clear summary and/or background
- Steps to reproduce (if applicable)
  - Be specific!
  - Provide sample code or screenshots if relevant
- What you expected would happen
- What actually happens
- Notes (including why you think this might be happening, or workarounds you've tried)

Thorough reports help us improve the course materials!

## Use Consistent Formatting and Style

- **Quarto files (.qmd):** Follow the existing structure for slides, exercises, and course content
- **R code:** Write clean, readable, and well-commented R scripts
- **Markdown:** Use consistent heading levels and formatting
- Look around the codebase to get a feel for the style conventions
